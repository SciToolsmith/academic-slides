# 语义布局与视觉形式选择

先判断页面任务和证据，再选择表达形式和布局。布局库是候选集合，不是固定页序。

## 决策顺序

```text
页面要回答的问题
→ 中心结论
→ 证据类型与数量
→ 最合适的视觉形式
→ 布局家族
→ 文字压缩与层级
→ 可编辑实现
```

如果现有布局无法自然容纳内容，使用自由正文画布；不要通过缩小字号或制造无意义卡片强套模板。

布局选择采用三级优先级：

1. 封面、目录、章节过渡和结束页优先复用通用壳层。生产型毕业答辩保留目录，并默认为每个主章节使用完整过渡页；只有已记录的用户要求或紧凑结构理由才能使用集成过渡。其他 profile 按其叙事需要决定。
2. 正文优先选择与证据关系、信息数量和阅读顺序自然匹配的注册版式。
3. 没有自然匹配时，直接按设计令牌组合新的可编辑画布；`free_canvas` 是正式能力，不是异常回退。

布局注册表只说明何时适用，不构成白名单。不得因为库中存在三栏、四步、五结论、树状或辐射版式，就改变论文原本的项目数量与逻辑关系。新增的自定义正文布局应继续遵守安全区、字体、主题、来源和可编辑性规则，并在 `layout.rationale` 中说明为何没有采用现成版式。

自定义正文可采用两种实现：简单混合证据用 `free_canvas` 的 `render_data.custom_elements` 明确给出可编辑的 `text`、`metric`、`shape`、`image`、`formula`、`connector`、`annotation` 和 `highlight`；复杂且会复用的论文专属结构，可在内部项目构建源中新增具名 renderer。交付的同名 MJS 必须嵌入最终项目规格并仅引用包内相对资产，不能依赖未交付的 deck spec 或本机路径。两者都允许选择 `standard`、`minimal` 或 `none` 页眉模式。构建器遇到未知布局必须报错，不得静默回退到普通卡片页。

```json
{
  "layout": {
    "family": "free_canvas",
    "variant": "custom:paper-specific-evidence",
    "rationale": "现有版式无法忠实表达本页的证据关系",
    "reading_order": ["主结论", "主证据", "解释与边界"]
  },
  "render_data": {
    "chrome": "standard",
    "custom_elements": [
      {"type": "image", "asset_ref": "fig-main", "x": 64, "y": 176, "w": 650, "h": 380},
      {"type": "highlight", "geometry": "ellipse", "x": 330, "y": 260, "w": 130, "h": 90,
       "color": "emphasis"},
      {"type": "connector", "direction": "right", "x": 704, "y": 310, "w": 90, "h": 18,
       "color": "secondary"},
      {"type": "text", "text": "由证据直接支持的结论", "x": 830, "y": 190, "w": 370, "h": 130,
       "style": {"fontSize": 26, "bold": true, "color": "primaryDark"}},
      {"type": "annotation", "text": "评委应直接查看的曲线特征", "x": 830, "y": 360, "w": 350, "h": 74,
       "fill": "primaryLight", "color": "emphasis"}
    ]
  }
}
```

`connector` 只表示单段可编辑方向关系；分支或折线连线用多段 connector 组合，不得穿过文字。`formula` 引用已经单一公式管线验证的 LaTeX 或内置 MathJax SVG/PNG 资产；`highlight` 与 `annotation` 必须指向具体证据，不作装饰。元素颜色优先使用 `primary`、`primaryDark`、`secondary`、`emphasis`、`warning` 等语义 token，正式规格不直写颜色值。

## 语义强调层

先用字号、字重、位置和留白建立层级，再决定是否使用强调色。高质量不等于每页标红；只有核心数字、关键差异、决定性判断、风险或边界值得局部强调。

- 每页通常 0–1 个主强调，必要时再加 1 个次强调；不得超过 2 段、合计 32 个着色字符。
- `strong` 只加粗；`key`、`result`、`decision` 使用主题的正文强调色；`warning`、`critical`、`success` 使用固定语义色并同时保留文字或符号说明。
- 蓝、青、紫主题可用克制的深朱红突出结论；红色主题改用对比足够的深赭金，避免红上加红。颜色值由主题解析，页面内容不得直接写 hex。
- 封面、目录、章节首页、结束页依靠构图层级，不使用局部彩色文字。导航、图注、来源和普通元信息也不抢强调色。
- 深色底上的白字优先保持白色并加粗，避免为了“标红”降低投影对比度。
- 同一颜色在全稿保持同一语义；去色后结论、风险和状态仍须可理解。

`text_emphasis.text` 必须是最终可见文字中的唯一精确子串；重复时用稳定的 `shape_name` 消歧。示例：

```json
"text_emphasis": [
  {"text": "下降 20.2%", "role": "result"}
]
```

兼容字段 `content.bullets[].emphasis` 仅用于整条项目符号的 `strong`、`accent` 或 `warning`；需要强调局部数字或关键词时优先使用 `text_emphasis`。

## 常用布局家族

| 布局家族 | 适合内容 | 避免情形 |
| --- | --- | --- |
| `hero_figure` | 单幅关键图、装置、系统总览、主结果 | 图片只是装饰或清晰度不足 |
| `comparison` | 优化前后、理论对照、案例对照、方法比较 | 对象不可比或比较维度不一致 |
| `chart_insight` | 一个主图表与一条结论 | 多张无关联小图 |
| `figure_formula` | 图片或结果与一个解释性公式 | 公式与页面结论没有直接关系 |
| `process_flow` | 连续步骤、输入处理输出 | 并列观点、章节罗列 |
| `system_architecture` | 模块、层级、依赖和接口 | 单一路径可用简单流程表示 |
| `evidence_chain` | 命题、材料与推论的关系 | 仅有时间顺序 |
| `quote_analysis` | 核心短引文、编码或文本解释 | 大段原文或无明确分析焦点 |
| `case_matrix` | 多案例、多维度对比 | 维度太多导致表格不可读 |
| `method_design` | 样本、变量、实验或研究设计 | 细节应放附录时 |
| `validation_matrix` | 多项指标、多来源互证 | 单个结果即可说明时 |
| `contribution_limits` | 贡献、边界和展望的对应关系 | 首次提出未展示的新结论 |
| `free_canvas` | 特殊语义或布局库不匹配 | 可由现有布局清楚表达时 |

章节页、封面、目录和结束页在需要时使用专门布局，不与正文布局抢夺视觉复杂度；它们不是每个项目都必须出现的固定页。

## 图片决策

使用图片时必须回答：它证明什么、评委需要看哪里、是否清晰、是否需要对照或标注。优先使用论文原创结果和能直接支撑结论的图片。

- 单图承担主证据：放大并配一条结论，不用多个装饰框分散注意力。
- 双图比较：保持尺度、视角、色彩和标注含义可比。
- 多图序列：仅在时间、步骤或层级关系明确时使用。
- 图内文字过小时重绘关键标注或局部放大，不只整体放大低清截图。
- 引用图必须标记来源性质，不能暗示为作者成果。

## 图表与表格决策

- 有趋势、分布、关系或对比时优先图表。
- 需要精确查值且数据量有限时使用表格。
- 只突出与中心结论相关的系列，同时保留必要基准、误差和单位。
- 每张图表配一条明确结论；颜色和图例跨页一致。
- 不使用 3D 图表、无意义渐变或过度装饰降低读数准确性。

## 公式决策对象

每页在 `formula` 中明确：

- `include`：是否使用；
- `reason`：为何需要或不需要；
- `equation_ref` 与 `source_refs`：论文定位；
- `latex`：经过核对的表达式；
- `role`：定义、目标函数、约束、方法核心或结果解释；
- `variables_to_explain`：本页必须解释的变量；
- `plain_meaning`：一句话含义。

公式通常放在结论下方或证据旁边，变量解释靠近公式。不要把公式当背景纹理。

## 流程图决策对象

每页在 `diagram` 中明确：

- `include` 和 `reason`；
- `source_refs`；
- `nodes`、`edges` 和 `direction`；
- `output`：流程最终得到什么。

节点使用平行动词或名词短语；箭头只表达真实关系；分支标注条件；循环标注反馈。优先使用 PowerPoint 原生形状，确保文字和关系可编辑。

## 科研证据画布门禁

科研正文不是“把图放进卡片”，而是让公式、图、直接标注与结论组成一条可核验的解释链。技术核心页在首次完整构建前运行：

```bash
node scripts/validate-scientific-design.mjs deck-spec.json --strict
```

至少遵守以下规则：

- 流程图的形状必须服从论文关系。`diagram.edges` 存在分支、汇合、反馈、循环或节点多入/多出时，不得选择 `four-step-ribbon`、线性时间线、阶梯或流水线版式。并网/离网等共享基础后的并行分析应使用分叉—汇合、泳道或自由证据画布；控制闭环必须画出反馈。
- 核心结果与验证页必须有已渲染的第一落点：可编辑 `text_emphasis`、已选中的 `ready/` 标注/局部放大/拆分资产，或自由画布中真实的 `annotation`/`highlight` 至少一种。`visual_focus` 和 `annotation_plan` 只记录设计意图，未被渲染器消费时不能独立通过落实门禁。不能只把两张复杂曲线缩进双栏，再把关键频点写在页脚。
- 上一条只证明页面具有视觉焦点。在 `group_meeting_v2` 中，核心发现还必须让 renderer 真正消费对应的源图、表、源文本摘录或公式证据；`text_emphasis` 单独不能满足源证据合同。
- 原论文图只做 `contain` 或普通裁边不算演示化处理。评委需要定位读图位置时，应按证据需要选择标注、局部放大、拆分面板或忠实重绘；不得为了通过门禁添加没有信息的箭头。
- 复杂 chart/diagram 进入双栏前必须有 `annotation_plan`。若坐标轴、图例、单位或子图文字在投影尺度不可读，放大、拆页或从可靠数据忠实重绘，不能继续缩小。
- 标题可承担结论，但同一句结论不得再原样出现在 `takeaway` 与底部结论条。其余空间用于证据、解释或适用边界。
- 连续三页使用同一布局 variant 应说明分析上的必要性，否则更换与证据关系更匹配的画布；版式变化不是装饰轮播。
- 生产型 `final_defense` 的技术核心页不能全稿零强调且没有显式视觉焦点。强调只用于证据承载的数字、差异、曲线特征、判断或边界，不要求每页着色。

`layout_gallery` 是布局能力展示，不代表生产叙事，必须显式设置 `artifact_purpose: "layout_gallery"`。画廊只豁免生产叙事门禁；布局—拓扑不匹配、伪自定义画布、通用 schema、资产存在性和渲染可读性仍须检查。正式项目不得借用该标志绕过检查，画廊也不得通过项目 MJS 或交付暂存脚本伪装成客户 production 交付。

建议把视觉焦点记录为简短字符串或对象：

```json
{
  "render_data": {
    "visual_focus": "在两幅扫频曲线上直接标出 45 Hz、650 Hz 与 2500 Hz",
    "annotation_plan": {
      "left": "45 Hz 敏感峰",
      "right": "650 Hz 谐振与 2500 Hz 特性反转"
    }
  }
}
```

这些字段记录设计意图，不替代渲染后的逐页可读性检查。

## 文理兼容的表达选择

- 理论与概念：概念关系、层级、谱系或对立维度；
- 文本与史料：短引文 + 关键词强调 + 解释，不展示整页扫描件；
- 案例研究：案例矩阵、时间线、机制链；
- 统计与实证：样本/模型最小信息 + 核心效应 + 稳健性；
- 实验：装置/条件 + 测量 + 误差 + 结果；
- 工程设计：需求/约束 + 方案 + 优化 + 多维验证。

不要因为模板存在树、辐射图或三卡片，就把本无该结构的内容改写成这些形状。

## 信息密度与可读性

- 一页一个主要结论，必要时一个次级解释。
- 正文尽量使用短句；长定义、引文和方法细节放讲稿或附录。
- 保持明确阅读顺序：标题 → 结论 → 主证据 → 解释/限定。
- 不依赖颜色作为唯一编码；兼顾投影、色觉和黑白打印。
- 所有图片、公式、表格和图表在实际投影尺度上可辨认。
- 页面轮廓应有节奏变化，但相同语义保持一致。
