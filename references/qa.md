# PPT 质量检查

QA 同时覆盖学术内容、证据、叙事、视觉和技术。结构检查不能替代逐页渲染检查。

## 检查顺序

1. 校验 `project-config.json`、`paper-assets.json`、`paper-index.json`、`evidence-index.json` 和 `deck-spec.json` 的 JSON Schema。
2. 执行跨文件与跨字段语义检查。
3. 对正式项目执行 `node scripts/validate-project.mjs <project-dir> --stage deck --require-schemas`；它同时调用布局/渲染真实性检查和组会科学内容合同。布局画廊显式使用 `artifact_purpose: "layout_gallery"` 豁免生产叙事。
4. 构建 PPTX、Word 发言稿和项目 MJS。
5. 渲染所有幻灯片和联系表一次；使用 `node scripts/render-word-qa.mjs --input <发言稿.docx> --output-dir <内部QA目录>` 将 Word 渲染为逐页 PNG 一次。该包装器继续调用 Documents Skill 的 `render_docx.py`，并为 bundled LibreOffice 显式加载其 `fontconfig/fonts.conf`，避免 macOS 中文字体被错误替换为空白。
6. 先看全稿联系表和节奏，再对核心结果、公式、表格、复杂科研图、自由画布、自动风险页、封面和结束页做全尺寸复核；普通单篇组会通常最多检查 8 张全尺寸风险页，简单过渡页不必逐张像素级检查。检查 Word 标题、分页、逐页编号和讲稿顺序；来源继续在 PPT 备注中核对。
7. 检查 PPT 备注、Word、媒体、字体、公式、MJS 可复现性和可编辑性。
8. 修复后只复查受影响页面；主题、字体、母版、全局间距、导航或渲染器变更才触发全稿复查。

## 学术与证据 QA

- 标题、摘要、正文、图表和结论口径一致。
- 数字、单位、有效位数、样本量和百分比正确。
- 每个入选公式逐项核对符号、上下标、编号与量纲；不扩展为全论文公式审校或推导正确性证明。
- 图表结论不超出图表能证明的范围。
- 相关性没有改写成因果性。
- 贡献、创新和“首次”等表述有直接证据。
- 自行计算可从记录的输入与公式复算。
- 论文原创、论文引用和外部补充被清楚区分。
- 论文内部矛盾没有被静默掩盖。
- 核心主张在 `claim_evidence_map` 中均有可定位证据。
- 文献组会的核心发现页真正渲染对应的源图、表、源文本摘录或公式证据；纯文字强调不能代替证据闭环。

## 叙事 QA

- 全稿能用一句话解释主线。
- 每页只有一个主要任务和清晰中心结论。
- 前置概念在使用前已解释。
- 方法篇幅不挤占结果和验证。
- 结果之后有充分验证或边界说明。
- 贡献能回指前面展示的证据。
- 页面之间有自然过渡，没有重复论证。
- 默认无可见附录，学生结束页必须是最后一张。
- 用户提供时长时，预计讲述总时长落在合理近似范围且留有缓冲；未提供时只检查讲稿节奏与页间比例。

## 视觉 QA

- 页面没有溢出、遮挡、异常换行、裁切错误或对象跑位。
- 标题、正文、图注和数字层级清楚。
- 图片清晰，图例、坐标轴、单位和关键标注可读。
- 对比图尺度和视觉编码一致。
- 公式清晰，变量解释靠近公式；页面不得出现 raw LaTeX 命令。
- 流程图关系真实，箭头、分支和循环无歧义。
- 分支、汇合、反馈或循环关系没有被线性 ribbon、时间线、阶梯或流水线模板扭曲。
- 不存在为填空而画的流程图、树形图或卡片。
- 核心结果与验证页把 `visual_focus` 真正落实为局部强调、已处理证据资产或直接图上标注；复杂双栏科研图的 `annotation_plan` 已转化为实际可见处理，不只停留在元数据。
- 核心论文图不止做普通裁边或 `contain`：需要评委定位的证据已按需标注、局部放大、拆分或忠实重绘。清晰且无需定位小区域的辅助图可保留忠实 crop，不为消灭建议警告强行画箭头。
- 标题、takeaway 和底部结论条没有重复同一句结论；连续三页同一布局 variant 已有证据关系上的理由。
- 页面不过密，也不因装饰造成空洞。
- 颜色、字体、页码、导航和章节规则一致。
- 眯眼检查每页只有一个第一落点；局部强调不超过 2 段且没有把普通信息全部染色。
- 强调角色与颜色语义全稿一致；红色不被滥用于普通重点，警示色不被误用为装饰色。
- 去色后关键结论、状态和风险仍可理解；强调文字在实际背景上保持足够对比度。
- 强调没有造成孤字、标点落单、换行、遮挡或与图例争夺注意力。
- 颜色不是唯一信息编码，投影环境下仍可辨识。
- 文献组会唯一封面在第一页且有汇报人与日期；唯一学生结束页在最后一页。讨论、总结和下一步位于其前，不在结束页后附加“复现清单”或审计页。
- 老师可见页面不出现 `PAPER REVIEW`、生成器、QA、证据 ID、逐页渲染、完整性检查、MJS、交付包等后台生产语言。机构明确要求的 AI 披露按要求执行，不由 Skill 自动添加。

## 技术 QA

- PPTX 能正常打开、保存和播放。
- 页面顺序、总页数、章节和 `deck-spec.json` 一致。
- 每页备注包含讲稿和 `[Sources]` 区块。
- Word 发言稿与 PPT 备注来自同一 `speaker_notes`，页面数量、顺序、讲稿和过渡一致；PPT 每页保留一个 Sources 区块，精简 Word 默认不重复展示 Sources。
- Word QA 同时满足三项：OOXML 中中文正文完整、PDF/PNG 使用可识别的 CJK 字体、逐页 PNG 中文可见。Darwin 下包装器另生成 QuickLook 缩略图作为原生解析交叉检查。若结果为 `runtime-limited`，这是 LibreOffice 字体解析环境限制，不得据此改写、图片化或嵌入整套正文字体；应改用原生 Word/QuickLook 复核并在内部 QA 记录限制。QuickLook 缩略图只验证原生中文显示，完整页数仍以修复后的逐页渲染或原生 Word 导出为准。
- 项目 MJS 不读取未交付的 deck spec，不含本机绝对路径，能使用包内相对资产重建同名 PPTX 和 DOCX。
- 所有外链媒体已按交付策略嵌入或明确说明。
- `theme.fonts` 只使用 profile 声明的主字体或回退字体，且中文标题/正文使用同一可验证字体；不得临时写入 Heiti SC 等未声明字体。在 PowerPoint 与 QA 渲染器中都不应出现严重替换、方框或字符丢失。
- 公式资产来自已核对的源：优先使用本地 LaTeX 同源生成的 SVG/PNG；无 LaTeX 时允许内置 MathJax 路径 SVG。检查 SVG 不含 `<text>` 或外部字体依赖、没有错误提示，且 SVG 或兼容 PNG 在目标软件中正确显示。
- 关键文本、形状、图表和流程图保持可编辑；无法编辑的部分有合理原因。
- 未包含临时路径、敏感信息、无关文件或失效资源。
- 交付目录、PPTX 和 MJS 使用相同的“短题名_汇报类型”basename；DOCX 在同一 basename 后仅追加 `_发言稿`。全部名称不含姓名、日期、版本或最终版标记。
- 客户包根目录只有同名 PPTX、同名 MJS、同名 `_发言稿.docx` 与 `assets/`；不存在 deck spec、大纲、证据索引、QA、预览、日志、源 PDF、`node_modules` 或空素材子目录。

## 跨字段语义检查

JSON Schema 之外至少检查：

- `page_policy=fixed` 时目标页数与实际页数一致，或有偏差说明；
- 幻灯片 `order` 唯一且连续，`id` 唯一；
- `section_id` 能在 `sections` 中找到；
- 所有 `evidence_refs`、`source_refs` 和资产 ID 可解析；
- `formula.include=true` 时存在公式内容、角色和来源；
- `diagram.include=true` 时至少有节点、关系和明确输出；
- `diagram.edges` 含分支、汇合、反馈、循环或非线性拓扑时，布局不得使用线性 variant；
- 技术核心页不能全稿只有 `strong` 或零强调；需在少数证据页落实可编辑语义强调；
- 核心结果/验证页至少具有已渲染的 `text_emphasis`、已选中的 `ready/` 处理资产或自由画布直接标注之一；`visual_focus`/`annotation_plan` 元数据本身不计为落实；
- 上一条只检查页面是否有第一落点；组会核心发现仍必须实际渲染源证据，`text_emphasis` 单独不能满足 `group_meeting_v2`；
- included 科研图只有 `crop/contain` 且无标注、拆分、局部放大或重绘时产生警告；核心结果或验证页在严格模式中可升级，非核心清晰原图为 advisory，不阻塞交付；
- 复杂 chart/diagram 放入双栏且未落实定位处理时产生警告；核心页可升级，辅助页为 advisory；
- 标题、takeaway 与 `render_data` 结论重复，以及连续三页同一 layout variant，均在完整构建前报告；
- `figure_count` 与图片记录数一致；
- 备注预计秒数之和与 deck 级 `estimated_seconds` 一致；仅在用户提供时长时检查其与时长软约束的近似关系；
- 核心主张至少映射到一页和一项证据；
- `group_meeting_v2` 至少有一条证据绑定的 `presenter_synthesis` 或 `presenter_critique` 真正映射到主稿，且核心论文发现保持 `source_author_claim`；
- “优于/提升/超过基线”若只有 `objective` 或 `training` 证据则失败，必须补比较、独立验证、稳健性证据或缩小表述；
- 所有文件哈希与磁盘内容一致。

## 严重级别与停止条件

### 硬失败

出现以下问题不得正式交付：文件无法打开、源文件缺失、核心数字或入选公式错误、证据引用断裂、组会核心发现无实际源证据、公式中心论文零核心公式、严重溢出遮挡、备注或页面大量缺失、敏感信息泄露。

### 重要警告

包括页面过密、图片偏糊、叙事重复、主题对比不足、来源定位不够精确，以及在用户提供时长时明显偏离时间预算。应修复；无法修复时在 QA 报告中说明影响与建议。

### 可接受提示

包括不影响理解的轻微字距、非核心资产的低风险兼容差异、辅助图未做额外标注、轻微布局重复和边缘留白。`balanced_95` 下这些 advisory 不因 `strict` 自动升级；不要为追求形式上的零提示无限返工。

### 默认回修边界

默认执行一轮完整检查和一轮针对性修复。硬失败必须继续处理；其余问题只有在明显改善学术准确性、叙事、投影可读性或兼容性时才继续。像素级相似度、无害元数据、边缘留白和轻微字距不构成继续返工的理由。

局部页面修改后只复查受影响页及其前后衔接页。只有全局设计或生成逻辑变化才重新做一次全稿检查。

## 最终报告

在内部工作区记录检查时间、输入版本、构建命令、渲染方式、通过项、剩余警告和已知限制；QA 报告不进入客户包。硬失败为零且重要警告已修复或明确披露时即标记为可交付并停止，不再为可选润色消耗额外轮次。

维护或发布 Skill 时，先运行 `scripts/validate-skill-assets.mjs --profile release --strict`；它已包含规定的测试、确定性 eval 和预发布打包检查。只有实际写出发布暂存目录或压缩包时才再次调用 `package-skill.mjs`，不要单独重复运行全套测试或 `run-skill-evals.mjs`。只有隔离失败、采集耗时或开发某项测试时才定向运行对应命令。真实模型触发、叙事质量与视觉判断仍需代表性人工抽查；确定性脚本不得把结构覆盖率伪装成模型质量分数。
