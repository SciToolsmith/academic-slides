# 质量检查与停止条件

结构检查、科学支持核对和渲染检查各有职责。JSON 齐全、图片存在、角色标签齐全或脚本 PASS 都不能证明论文讲对了。

## 按交付范围检查

1. 检查 project/paper/evidence/asset/deck 的 schema、稳定 ID、路径、源文件哈希和跨文件引用；运行 `node scripts/validate-project.mjs <project-dir> --stage deck --require-schemas`。
2. 运行科学内容和设计校验器。检查引用与实际渲染关系，记录其风险提示；不要把启发式判断包装为科学正确率。
3. 对核心主张及入选证据进行独立支持程度核对。
4. 构建并渲染整个 PPT，先看联系表，再全尺寸看核心结果、方法/公式、密集图表、自由画布和风险页。
5. 交付 Word 时运行 `scripts/render-word-qa.mjs` 并检查其与 PPT 备注的页序和讲稿同步；仅 PPT 的任务不执行 Word QA。
6. 交付重建包时在干净暂存目录验证 MJS、资产和构建环境记录；环境漂移不能静默继续。

## 科学与证据

- 元数据、数字、单位、样本口径、有效位数和派生计算能回到来源。
- 核心结论真正被展示的证据支持；相关性不写成因果，训练目标不冒充独立比较。
- 比较主张有对象、指标、条件与不确定性。否定、条件和限定语保持原意，不能靠换词绕过证据要求。
- 作者结论、图表事实和汇报者判断分离；批判指向具体证据，未报告某项信息不直接等于作者做错。
- 入选公式核对上下标、符号、编号和量纲；无需审计无关的全文推导。
- 核心发现有 source-backed 可见证据，引用和备注能复核；来源 ID 或强调文字本身不构成证据。
- 独立核对者用源图/原文和上下文审查“支持 / 需缩小范围 / 不支持”，记录有定位的问题，不能只检查生成者自评。

## 裁图与处理记录

- 自动裁图是 `unverified` 候选。将入选图与源页及完整 caption 对照，检查所有必要面板、坐标轴、图例、样本与误差含义，并排除相邻正文。
- 核验绑定具体 `asset_sha256`。替换裁图后重新核验。
- `ready/` 只是目录名；派生处理要能回溯输入/输出资产、哈希、操作与理由。字节变化证明发生变化，不证明变化忠实。
- 清晰原图经目标尺寸检查可以保持原样；明确无需处理的原因。不要强制每张图重画、加箭头或着色。
- 每页视觉焦点应能帮助阅读具体证据；声明 `visual_focus` 但未呈现出来不算落实。

## 叙事和视觉

- 先让听众知道本次问题与主线；每页有一个主要任务，概念在使用前得到必要解释。
- 逐篇精读遵守所选章节导航；问题比较先交代比较轴，并清楚标明各篇证据归属、方法与边界。
- 主标题可以表达判断，章节标签只作导航；重复标题与结论条不挤占证据空间。
- 用户提供的模板、语言和附录需求有明确配置，不把默认样式当作硬失败。
- 没有溢出、遮挡、异常换行、错误裁切或失真关系；图内文字在投影尺度可辨。
- 表格与图表保留单位、误差和必要对照；不同口径不制造虚假横向比较。
- 核心发现的第一落点清楚；颜色不是唯一编码。局部强调应有意义，不追求固定数量。

## 文件与兼容性

- PPTX 能打开、保存和播放，页面顺序与规格一致，每页备注有讲稿和 Sources。
- 文字、表格、支持的图表和简单关系图应可编辑。源图和复杂公式可能是图片；提供 TeX 重建源不等于原生 PowerPoint 公式。
- Word 仅在相应模式检查。若 LibreOffice 字体环境限制，使用原生 Word/QuickLook 核验并记录限制，不能把中文正文图片化掩盖问题。
- 重建入口只引用包内资产，并记录实现/模板/schema/runtime 的版本或哈希。旧包未固定环境时如实说明；迁移是一次新构建，应重新 QA。
- 根据 delivery mode 检查输出白名单；不把源论文、内部索引、QA、缓存、日志或密钥混入客户包。

## 修复和停止

硬失败必须解决：无法打开、核心值/公式错误、源证据断裂、错误或不完整裁图、严重不可读、媒体损坏、备注大量缺失或敏感信息泄露。

重要问题包括叙事重复、论证不足、图片模糊和明显超出用户预算。修复；不能解决时明确披露限制，不声称完整达标。辅助图无需标注、小留白、轻微字距等提示不要求继续返工。

完成首轮检查后集中修复；仍有重要问题时继续。局部变化只检查受影响页及衔接页，全局主题、字体、导航或 renderer 变化才重查整稿。内部记录来源版本、命令、结果和未解决问题。

维护/发布运行 `node scripts/validate-skill-assets.mjs . --profile release --strict`，已含规定测试和打包检查。真实行为与作品评测另见 `references/evaluation.md`，避免反复跑与当前改动无关的全套检查。
