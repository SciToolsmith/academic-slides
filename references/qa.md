# PPT 质量检查

QA 同时覆盖学术内容、证据、叙事、视觉和技术。结构检查不能替代逐页渲染检查。

## 检查顺序

1. 校验 `project-config.json`、`figures.manifest.json` 和 `deck-spec.json` 的 JSON Schema。
2. 执行跨字段语义检查。
3. 构建 PPTX、Word 发言稿和项目 MJS。
4. 渲染所有幻灯片和联系表一次；渲染 Word 为逐页 PNG 一次。
5. 先看全稿节奏，再逐页全尺寸复核一次；检查 Word 标题、分页、讲稿和 Sources。
6. 检查 PPT 备注、Word、媒体、字体、公式、MJS 可复现性和可编辑性。
7. 修复后只复查受影响页面；主题、字体、母版、全局间距、导航或渲染器变更才触发全稿复查。

## 学术与证据 QA

- 标题、摘要、正文、图表和结论口径一致。
- 数字、单位、有效位数、样本量和百分比正确。
- 公式逐项核对符号、上下标、编号与量纲。
- 图表结论不超出图表能证明的范围。
- 相关性没有改写成因果性。
- 贡献、创新和“首次”等表述有直接证据。
- 自行计算可从记录的输入与公式复算。
- 论文原创、论文引用和外部补充被清楚区分。
- 论文内部矛盾没有被静默掩盖。
- 核心主张在 `claim_evidence_map` 中均有可定位证据。

## 叙事 QA

- 全稿能用一句话解释主线。
- 每页只有一个主要任务和清晰中心结论。
- 前置概念在使用前已解释。
- 方法篇幅不挤占结果和验证。
- 结果之后有充分验证或边界说明。
- 贡献能回指前面展示的证据。
- 页面之间有自然过渡，没有重复论证。
- 附录包含重要防守材料但不干扰主线。
- 预计讲述总时长落在合理近似范围，且留有缓冲。

## 视觉 QA

- 页面没有溢出、遮挡、异常换行、裁切错误或对象跑位。
- 标题、正文、图注和数字层级清楚。
- 图片清晰，图例、坐标轴、单位和关键标注可读。
- 对比图尺度和视觉编码一致。
- 公式清晰，变量解释靠近公式；页面不得出现 raw LaTeX 命令。
- 流程图关系真实，箭头、分支和循环无歧义。
- 不存在为填空而画的流程图、树形图或卡片。
- 页面不过密，也不因装饰造成空洞。
- 颜色、字体、页码、导航和章节规则一致。
- 眯眼检查每页只有一个第一落点；局部强调不超过 2 段且没有把普通信息全部染色。
- 强调角色与颜色语义全稿一致；红色不被滥用于普通重点，警示色不被误用为装饰色。
- 去色后关键结论、状态和风险仍可理解；强调文字在实际背景上保持足够对比度。
- 强调没有造成孤字、标点落单、换行、遮挡或与图例争夺注意力。
- 校徽比例、留白、颜色和底色使用符合来源说明。
- 颜色不是唯一信息编码，投影环境下仍可辨识。

## 技术 QA

- PPTX 能正常打开、保存和播放。
- 页面顺序、总页数、章节和 `deck-spec.json` 一致。
- 每页备注包含讲稿和 `[Sources]` 区块。
- Word 发言稿与 PPT 备注来自同一 `speaker_notes`，页面数量、顺序、讲稿、过渡和 Sources 一致；每页只有一个 Sources 区块。
- 项目 MJS 不读取未交付的 deck spec，不含本机绝对路径，能使用包内相对资产重建同名 PPTX 和 DOCX。
- 所有外链媒体已按交付策略嵌入或明确说明。
- 字体缺失不会造成严重替换或字符丢失。
- 公式资产来自已核对的源：优先使用本地 LaTeX 同源生成的 SVG/PNG；SVG 或 PNG 在目标软件中正确显示。
- 关键文本、形状、图表和流程图保持可编辑；无法编辑的部分有合理原因。
- 未包含临时路径、敏感信息、无关文件或失效资源。
- 交付目录、PPTX 和 MJS 使用相同的“短题名_汇报类型”basename；DOCX 在同一 basename 后仅追加 `_发言稿`。全部名称不含姓名、日期、版本或最终版标记。
- 客户包根目录只有同名 PPTX、同名 MJS、同名 `_发言稿.docx` 与 `assets/`；不存在 deck spec、大纲、证据索引、QA、预览、日志、源 PDF、`node_modules` 或空素材子目录。

## 跨字段语义检查

JSON Schema 之外至少检查：

- `page_policy=fixed` 时目标页数与实际页数一致，或有偏差说明；
- 幻灯片 `order` 唯一且连续，`id` 唯一；
- `section_id` 能在 `sections` 中找到；
- 所有 `evidence_refs`、`source_refs` 和资产 ID 可解析；
- `formula.include=true` 时存在公式内容、角色和来源；
- `diagram.include=true` 时至少有节点、关系和明确输出；
- `figure_count` 与图片记录数一致；
- 备注预计秒数之和与 deck 级预计时长一致；
- 核心主张至少映射到一页和一项证据；
- 所有文件哈希与磁盘内容一致。

## 严重级别与停止条件

### 硬失败

出现以下问题不得正式交付：文件无法打开、源文件缺失、核心数字或公式错误、证据引用断裂、严重溢出遮挡、备注或页面大量缺失、校徽机构错误、敏感信息泄露。

### 重要警告

包括页面过密、图片偏糊、叙事重复、主题对比不足、来源定位不够精确、时间预算明显偏离。应修复；无法修复时在 QA 报告中说明影响与建议。

### 可接受提示

包括不影响理解的轻微字距、非核心资产的低风险兼容差异。不要为追求形式上的零提示无限返工。

### 默认回修边界

默认执行一轮完整检查和一轮针对性修复。硬失败必须继续处理；其余问题只有在明显改善学术准确性、叙事、投影可读性或兼容性时才继续。像素级相似度、无害元数据、边缘留白和轻微字距不构成继续返工的理由。

局部页面修改后只复查受影响页及其前后衔接页。只有全局设计或生成逻辑变化才重新做一次全稿检查。

## 最终报告

在内部工作区记录检查时间、输入版本、构建命令、渲染方式、通过项、剩余警告和已知限制；QA 报告不进入客户包。硬失败为零且重要警告已修复或明确披露时即标记为可交付并停止，不再为可选润色消耗额外轮次。

维护或发布 Skill 时，额外运行 `scripts/run-skill-evals.mjs`、`scripts/validate-skill-assets.mjs --profile release --strict` 和精简发布打包检查。真实模型触发、叙事质量与视觉判断仍需代表性人工抽查；确定性脚本不得把结构覆盖率伪装成模型质量分数。
