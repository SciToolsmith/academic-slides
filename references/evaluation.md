# 用真实结果评估 Skill

确定性测试负责验证代码、数据合同和已知回归；`evals/skill-evals.json` 不调用模型，也不衡量 PPT 质量。一次通过不能证明模型会触发正确、证据正确或版面好看。

## 日常回归

维护改动先跑受影响的测试；发布前运行 release 检查。保留以下对照：相同图片改路径不改变处理判定；比较结论同义改写一致、否定不误判；长图注保留样本与误差信息；未核验裁图不能自称高可信；明确附录和比较叙事可以生成；不同交付模式只交付所请求格式；环境漂移在导入 renderer 前被发现。

## 独立行为与作品评测

选择有使用权限、可稳定取得的论文，记录论文 SHA256、来源、skill 提交、模型设置、runtime、提示词、耗时和实际交付文件。用同一输入对比修改前后；不把私有全文推送到开源仓库。

至少覆盖以下五种真实任务，先做最贴近当前改动的一个，再逐步积累：

| 任务 | 给独立执行者的请求 | 重点验收 |
| --- | --- | --- |
| 单篇实验论文 | “把附件做成组会 PPT，重点讲方法和核心图。” | 无颜色问卷；方法讲清；关键图和误差完整；默认只交付 PPT |
| 三篇存在分歧的论文 | “围绕三篇为何得出不同结论做对比汇报。” | 比较轴在前；每篇归属明确；不能只顺次缩略精读 |
| 理论/公式论文 | “解释核心模型，保留必要公式，附两页答疑材料。” | 公式忠实；备份页按要求生成；编辑范围如实 |
| 双栏和长图注论文 | “重点解释图 2 和图 4，不需要重画清晰原图。” | 裁图无漏轴/图例；完整图注；清晰原图不被迫加工 |
| 局部修改与重建 | “把第 5 页结论缩小到实验范围，其余保持不变。” | 来源不重做；相关备注同步；其余页无意外变化；漂移被明确处理 |

让执行者只获得请求、skill 和原始材料，不提供预期结论、失败案例或修复提示。评审者独立核对 source → claim → visible evidence，并查看渲染图；不要仅检查执行者填写的通过状态。真实材料不可得时可用标明为合成的样本测机械流程，但不能计入真实作品通过率。

## 记录有用的指标

- 科学：有多少核心主张被核对；数字/单位错误、无支持扩张、错误归因分别多少。
- 素材：入选图总数、漏裁面板/轴/图例数、邻栏正文混入数；核验绑定图片哈希。
- 可读性：无法辨认的关键标签、溢出/遮挡、需要人工修补的页面数。
- 任务适配：额外追问次数、违背明确要求的次数、未请求格式数量。
- 效率：总耗时、实际可获得的 token 使用、重复读取/整稿渲染次数、人工返工时间。不编造不可观测计费数据。

每项使用明确计数、源定位和实际截图佐证。主观的叙事/视觉评价记录理由；不要把多项分数合成一个看似精确的“科学质量 95 分”。新版本先要求不增加科学错误，再评估是否减少返工或改善讲述。

未执行的任务标为未执行；未做真实作品评测时只报告回归测试结果。代表性作品评测是持续积累的维护资料，不要求每次普通用户制作都展开完整评测工程。
