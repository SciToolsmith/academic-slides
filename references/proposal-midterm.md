# 开题与中期评审

`proposal_midterm` 使用一套共用视觉资产，但通过 `proposal` 与 `midterm` 两个 mode 实施不同的叙事和证据契约。页数、目录、章节和布局均随研究内容变化，不复制模板中的固定六部分。

## 共用原则

- 先确定本次评审要求评委判断什么，再选择证据与页面。
- 区分已有事实、研究假设、计划承诺、阶段观察、派生计算与预测。
- 既有文献证明研究背景或方法依据，不自动证明本项目已取得同样结果。
- 一页可合并多个叙事任务，但必须有一个中心判断与清晰证据顺序。
- 使用 `assets/proposal-midterm-universal/layout-registry.json` 作为优先设计词汇，不把 32 种布局当成页序或白名单；没有自然匹配时使用 `free_canvas`。
- 保留正式学术场景的机构标识、页眉与章节导航，但只使用已核验品牌素材。

## 开题 mode

开题要评委判断“这个问题是否值得做、问法是否清楚、方法是否能获得有效证据、资源和时间是否支持完成”。按研究内容自适应覆盖：

1. 研究背景、现实/理论价值与可核验缺口；
2. 研究问题、假设、理论命题或设计目标；
3. 总目标、研究边界、工作包及其真实关系；
4. 研究设计、方法、技术路线、数据/材料与验证口径；
5. 前期基础、资源、数据、平台、预实验或其他可行性证据；
6. 风险、备选路径、伦理、数据治理或其他关键合规条件；
7. 里程碑、依赖、预期交付物与评委需要判断的事项。

以上是语义覆盖，不是固定七章。短汇报可合并，方法复杂或前期证据充足时可拆分。

### 开题证据边界

- 缺口与现实需求引用原始文献、权威数据、标准或真实现场记录。
- 前期结果必须引用本项目的真实数据或实验记录；其他论文的结果只能作为背景。
- 创新主张应连接“缺口—新做法—验证路径”；没有依据时不使用“首次”“填补空白”。
- 假设、计划和预期成果的 `epistemic_status` 分别为 `hypothesis`、`planned` 或 `projected`，不写成 `observed` 或 `established`。

## 中期 mode

中期要评委判断“已批准目标完成到什么程度、阶段证据是否可信、偏差是否可解释，项目能否在剩余时间内收敛”。背景通常压缩为一页或省略，按内容自适应覆盖：

1. 已批准的原目标、工作包、里程碑和计划基线；
2. 截至 `as_of_date` 的完成、进行、延迟、变更或阻塞状态；
3. 真实阶段结果、质量控制、不确定性和可复核的支撑材料；
4. 计划与实际对照，以及时间、方法、范围或结果偏差；
5. 偏差原因、已采取/拟采取的纠偏措施与剩余风险；
6. 下一阶段任务、依赖、更新时间表、交付物和需要评委决策的问题。

不得在没有可比基线时制造“计划—实际”图，也不得在没有工作包或可复算口径时估算精确完成百分比。

### 中期证据闭环

- “原目标/原计划”引用 `approved_plan` 或 `research_proposal` 文档。
- “已完成/进行中/延迟”引用带日期的 `progress_evidence`、`midterm_report`、数据、图表、代码、实验或其他项目记录。
- 计划对照页同时引用至少一项 `plan_commitment` 和一项 `progress_update`/`completed_result`。
- 偏差记录通过 `related_evidence_ids` 关联基线与当前状态，并区分客观事实、原因解释和行动方案。
- 原计划缺失时，记录为限制，用可核验的最早项目记录作为低置信替代且显式说明；不反向虚构批准时的目标。

## 里程碑与时间

`milestone-analysis.json` 是计划、进展、偏差与下一步的结构化中间层。开题可以只有未来工作包与少量已完成的前期基础；中期至少有一个进展证据关联。

用户主动提供时长时，只将其作为近似内容预算，不将讲稿重写为逐秒计时稿；未提供时不询问、不虚构默认时长。结构页可合并或省略；不为使用目录、章节页、公式、技术路线或某个布局而增加页面。

## 备注与停止条件

每页备注先写自然发言稿和过渡，空两行后写 `[Sources]`；同一内容同步生成 Word 发言稿，不分别维护。计划、进展、偏差、风险、修正方案和时间表都要覆盖实际来源。

执行一次完整检查和一次针对性修复。数字、日期、状态、工作包、来源、品牌、遮挡、裁切和可读性是硬质量项；其余停止条件见 `references/qa.md`。
