```text
│       ├── logo.png
│       └── logo.meta.json
├── evidence-index.json

```

以上目录是 Codex 内部工作区，不是客户交付结构。`source/`、manifest、项目配置、deck spec、证据索引、联系表、logo 元数据和分析文件不得整目录复制给客户。

客户包只保留 `references/delivery.md` 规定的 `assets/`。先在内部建立一个“已筛选素材目录”，再交给 staging 脚本；不要直接传入完整工作资产库。交付侧按需创建 `figures/`、`formulas/`、`branding/` 和 `data/`；空子目录不创建。论文/单篇文献项目可按用户要求交付完整忠实图集与 `论文图片说明.md`；多篇文献组会默认只交付入选和重点分析图片。机器 manifest、联系表、公式临时 PDF、编译日志、品牌元数据、未使用素材和品牌候选不交付。交付 `data/` 只允许本稿真正依赖的 CSV/XLSX；内部 JSON 数据应在 MJS 中嵌入或转成受控表格，不直接散发。

论文图、表格、公式、校徽和装饰素材必须分开。不得覆盖 `original/`；裁白边、增强、标注、拆分或格式转换的结果放入 `ready/` 并记录转换过程。

正式构建只引用项目内已核验的本地资产。网页图片、出版页面截图和校徽先下载到对应资产目录并记录来源、访问日期与哈希；不要让最终 PPTX 在构建或播放时依赖远程图片 URL。

## 文献组会通用图表资产层

对每篇焦点论文运行一次：

```bash
node scripts/extract-paper-assets.mjs \
  <paper.pdf> \
  <project/assets/papers/paper-id>
```

输出 `paper-assets.json`、由其派生的 `论文图表资产说明.md` 和按需生成的 `assets/*.png`。JSON 是机器事实源；Markdown 只是供后续选材的简短阅读层，禁止两份手工分叉维护。全量索引在 MD 中只占一张 ID/图号/页码/短标题/状态表；只有入选或已物化项才展开图片与简要说明，并补 claim 映射、PPT 用途和呈现处理。

默认 `auto` 模式只在可检出图表数不超过脚本阈值 12 时物化全部 caption-free 裁图；超过阈值时建立完整 caption 轻索引，再由主张、方法、比较、稳健性与局限自动选出通常 6–8 个候选 ID，使用 `--select <id,id> --force` 定向物化。模型只深读候选，主稿通常使用其中 3–6 个父图。用户明确要求完整图集时可用 `--materialize all`，不增加人工审批门。

该提取器的承诺边界是“出生即数字且有文本层的常规论文 PDF”：

- 识别 `Figure/Fig./Table/图/表` 编号图注，以页面几何裁取 PNG；不宣称通用语义分割、矢量原件抽取或 OCR。
- 图身默认在图注上方，表体默认在表题下方；空间不足时只反向降级一次，低置信但不无限试裁剪框。
- 基线表格保留忠实 PNG crop，不批量转 CSV；只有入选表格且数据可复核时才结构化重建。
- 扫描件、非常规 caption 或复杂多栏版面可以标记低置信；如果它成为核心证据，才进行一次定向修正。
- 通用提取器不批量索引公式。核心公式在论文分析阶段写入 `evidence-index.json`，只渲染最终入选公式。

## 论文图片提取

1. 识别图注、图号、页码和图前图后正文。
2. 通用轻量路径使用去图注页面裁图；对入选的核心图，若 PDF 确有可稳定分离的嵌入位图或矢量原件，再优先替换为更高保真版本。
3. 遇到复合矢量、叠加文字、箭头、无法独立提取的多层图时，使用高分辨率页面裁切。
4. 图片本体通常不包含论文图注和正文；图内坐标轴、图例、箭头、子图编号和必要标签应保留。
5. 同一图号的多面板图默认保持整体；同页不同图号分别提取。
6. 用稳定 ID 和“图号 + 简短图名”命名；消除路径非法字符，但不要改变论文图号。
7. 文献组会按 `schemas/paper-assets.schema.json` 建立轻量清单；学位论文 legacy 资产流继续使用 `schemas/figures-manifest.schema.json`。
8. 校验“识别到的图注数、manifest 记录数、实际文件数”，解释所有差异。

低清、缺图例、裁切不完整或疑似引用外部资料的图片标记复核。不要默认使用生成式修复补出不存在的细节。

## 图片说明文档

文献组会的 `论文图表资产说明.md` 由 `paper-assets.json` 直接生成；学位论文 legacy 流的 `论文图片说明.md` 由 `figures.manifest.json` 生成。未入选资产只保留紧凑索引行，选中后才扩展为内容/作用、claim、PPT 用途和呈现处理；避免为未入选图表填完整富语义模板。

```markdown
## 图3.19 锁滚轮运动轨迹

![图3.19](original/图3.19 锁滚轮运动轨迹.png)

- 论文位置：第3章第3.3节；PDF第__页；论文页码第__页
- 图片内容：图中可直接观察到的对象和关系
- 在论文中的作用：它在论证链中承担什么任务
- 可支撑结论：与证据索引连接的结论，不夸大因果
- PPT使用价值：核心/辅助/附录/不建议
- 建议呈现：裁切、对比、标注、图例或布局建议
- 注意事项：清晰度、图例、单位、版权或解释风险
- 来源性质：论文原创结果/论文引用资料/无法确定
```

## 表格和数据图表

- 通用首轮提取先保留忠实截图作为校对真相；只有入选且数据可复核的表格才转为 CSV、JSON 或可编辑表格。
- 记录表号、标题、单位、脚注、样本口径和论文页码。
- 只有在数据可复核时重绘图表；保留输入数据、变换和计算说明。
- 不因视觉整洁删除会改变解释的误差线、显著性、样本量、单位或基准组。
- 大型表格应提炼主结果，完整表放附录。

## 公式

- 先建立公式索引，记录公式号、原始符号、页面、用途和上下文。
- 只渲染大纲已选中的核心公式；`.tex` 是唯一权威源，PDF 只是临时中间件。
- 将论文或模型生成的 LaTeX 视为不可信数据，只允许纯数学表达式。先运行 `scripts/render-formula.mjs --latex <表达式> --validate-only`；不得绕过其数学命令允许列表、危险控制序列拒绝和 `-no-shell-escape` 编译边界。
- 默认使用 `scripts/render-formula.mjs --latex <表达式> --output-dir <assets/formulas> --name <稳定名称>`。脚本优先调用本机 LaTeX；本机没有 LaTeX，或自动模式下本地编译失败一次时，直接回退到 Skill 内置的 MathJax 3.2.2 路径 SVG renderer。不要为每篇论文重复编写公式脚本，也不要要求用户为了单次汇报安装完整 TeX。
- 本机 LaTeX 可用时优先用 PDFLaTeX；表达式确有 Unicode 或中文时使用 XeLaTeX，并由同一源生成路径化 SVG 与透明高分辨率 PNG。需要直接验证零安装路径时使用 `--renderer mathjax`；内置 renderer 不访问网络，不需要 npm install，输出中的可见字形必须全部是 SVG path。
- 目标 PowerPoint 已验证支持 SVG 时使用 SVG；目标环境未知、旧版软件或 SVG 验证失败时，直接把 `asset_ref` 切换为 PNG。不要依赖 OOXML 自动生成的栅格 fallback。
- 本机没有 LaTeX 时，经过论文原文逐字核对的 ASCII LaTeX 表达式使用内置 MathJax SVG；Codex bundled runtime 中存在 `sharp` 时同源生成兼容 PNG。含中文、非 ASCII 字面字符、未支持宏或无法可靠转写的论文既有复杂公式，改用源 PDF 高分辨率忠实裁取。短而非核心的表达式才可使用逐字符核对的 Unicode 数学文本。
- 不得使用 raw LaTeX、搜索结果公式图片或未经验证的在线公式图片服务作为页面 fallback。复杂核心公式无法可靠渲染时停止并报告；非核心公式则移除或放入备注。
- 逐字核对上下标、希腊字母、括号、编号和量纲。
- 公式渲染不改变数学含义；解释文字与论文术语保持一致。
- 仅为排版可读性重排换行，不擅自简化或补全推导。
- 自动回退只允许本机 LaTeX 路径和内置 MathJax 路径各尝试一次，再做一次 SVG→PNG 兼容切换；不要无限尝试工具。MathJax 成功渲染不代表应扩大公式审校范围，仍只核对已入选公式的可见符号与来源。

## 校徽与学校品牌

检索顺序：

```text
识别学校和校区
→ 检查用户提供的官方素材或项目级已核验 catalog
→ 没有可用素材时搜索学校官网的品牌、视觉识别或下载页
→ 核验学校、校区、当前名称、素材类型和版本
→ 保存原文件与来源
→ 生成规范化 SVG 和透明 PNG
→ 在白底与深底上验证
```

本 Skill 不随包分发大学校徽。网络检索优先学校官网的视觉识别系统、品牌手册或官方下载页；不要直接使用搜索结果缩略图、来源不明聚合站或自行仿制的校徽。

如项目已有带来源的校徽目录，可使用 `scripts/find-university-logo.mjs <学校正式名> --catalog <项目内 catalog.json>` 查询。默认只接受标准化后的精确名称或别名。只有人工排查旧名、简称或拼写差异时才使用 `--fuzzy`；模糊结果始终是待核验候选，绝不能因名称相似直接放入 PPT。

项目内 `logo.meta.json` 至少记录：`institution_name`、`aliases`、`campus`、`asset_type`、`source_url`、`retrieved_at`、`sha256`、`transformations`、`usage_notes` 和 `verification_status`。未经核验的素材不得放入 PPT，也不自动写入 Skill 仓库。

不要擅自改色、改变比例、删掉校徽内部白色、添加阴影或重绘细节。找不到可信素材时使用学校正式文字标识，并在交付说明中标记；品牌素材缺失不得改变用户已经选择的主题预设。

## 资产选择与加工

- 在大纲阶段先选择稳定资产 ID，再制作 `ready/` 版本。
- 论文原创图与论文引用图必须区分；后者不能写成作者原创成果。
- 标注只突出已有证据，不添加论文未支持的结论。
- 裁切、旋转、增强、重绘和格式转换全部进入 provenance。
- 视觉素材应有 alt text 或可供讲稿使用的内容说明。
- 同一资产在多页复用时保持颜色、标注含义和裁切逻辑一致。
